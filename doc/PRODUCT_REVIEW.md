## 2. 👨‍💻 개발자 관점 보완점

### P0 (곧 문제가 되는 것)

1. **상시 테스트 스위트 부재**
   - 현재: 결정적 테스트를 `tsx` 임시 스크립트로 돌리고 폐기하는 패턴. 회귀 방지 자산이 안 쌓임.
   - 제안: Vitest 도입 → 기존 검증 로직(모션 wobble, ungroup 행렬, 오토키, 이징, bake 등)을 영구 테스트로 이전. `npm test` 한 방.
   - 부수효과: "브라우저 실동작 확인 대기"가 반복 병목 → Playwright E2E(로그인 세션 + 에디터 핵심 플로우)로 일부 자동화 가능.

2. **오토세이브 미결정** (`ViewportToolbar` 주석 상태)
   - 낙관적 잠금(`scenes.version`)이 이미 있어 재활성 리스크 낮음. 일반인 대상 서비스에서 저장 유실은 치명적.
   - 제안: 60초 디바운스 오토세이브 재활성 + 충돌 시(409) "다른 탭에서 수정됨" 안내.

3. **에러 모니터링 부재**
   - Sentry(또는 유사) 도입 — 특히 뷰어/임베드는 사용자가 오류를 신고할 방법이 없음.

### P1 (성능/부채)

4. **스토어 selector 리팩터** — NumInput 스크럽 시 캔버스 전체 리렌더(WORKLOG 기록). `liveTransformStore` 패턴을 다른 고빈도 편집에도 확대.
5. **Draco 실압축 미적용** — `dracoUrl` 필드만 있고 실압축 안 함. GLB 큰 씬에서 로딩 체감 차이 큼.
6. **인에디터 플레이 시 캔버스 2개** — MVP 허용이었으나 저사양에서 부담. 에디터 캔버스 `frameloop='never'` 일시정지 검토.
7. **InstancedMesh 자동 전환**(P4-01) — 배열/클로너로 수백 개 만들면 드로우콜 폭증.
8. **React Compiler eslint 에러 다수** — 신규 코드부터 클린 유지, 기존 것은 파일 단위 점진 정리.

### P2 (구조/보안)

9. **`run_script` 샌드박스** — 현재 제작자 자신 코드 수준(`new Function` + 제한 api). 마켓플레이스/리믹스 도입 **전에** iframe/Worker 격리 필수.
10. **커스텀 도메인 다중 씬** — `proxy.ts`가 경로 무시하고 기본 씬만 서빙. `go_to_scene`이 커스텀 도메인에서 반쪽 동작.
11. **커밋 메시지 전부 "수정"** — git 이력 추적 불가(PROGRESS.md가 대체 중). 최소한 기능 키워드 한 단어라도.
12. **에셋 씬 스코프** — 모델/텍스처/오디오가 `scene_data.assets[]`(씬 단위)라 같은 프로젝트 다른 씬과 공유 불가. 프로젝트 단위 승격 검토(Prefab도 동일).

## 3. 🎨 디자이너 관점 보완점

1. **한/영 라벨 혼재 (STEP 2b 중단)** — 상단바/GNB는 영문, 인스펙터 일부·EventsSection은 한글. 범위(타이틀만 vs 전부) 확정 후 스윕 완료 필요. *장기적으로는 i18n 사전 분리가 정답(한국어 사용자도 많을 서비스).*
2. **문장형 이벤트 2단계** — 목록은 문장 카드("When 클릭 → 팝업 표시")로 완료, **추가/편집 폼은 여전히 전통 폼**. 인라인 pill 편집(문장 속 빈칸을 클릭해 채우는 방식)이 비개발자 접근성의 핵심 마일스톤.
3. **모바일/태블릿 대응** — 뷰어는 모바일 지원(터치 이동·E 버튼), **에디터는 데스크톱 전용인데 안내가 없음**. 최소: 모바일 접속 시 "데스크톱에서 편집하세요" 화면. 중기: 태블릿 뷰 전용 모드.
4. **접근성(a11y)** — 키보드 내비게이션·ARIA·색 대비 체계 점검 이력 없음. 커스텀 드롭다운(`useDropdown`+`useListNav`)은 키보드 대응이 있으나 전수 검증 필요.
5. **인터랙티브 튜토리얼 부재** — 빈 상태 코칭·프리셋·온보딩(EditorOnboarding)은 있으나 "첫 게임을 5분 만에" 단계형 워크스루(코치마크 체인)가 없음. 일반인 온보딩의 마지막 조각.
6. **로딩/스켈레톤 일관성** — 씬 로드, GLB 업로드, 병합/Boolean(bake) 중 진행 피드백이 토스트/버튼 busy에 의존. 통일된 진행 UI 검토.
7. **아이콘/타이포 시스템 문서화** — lucide 전면 교체는 완료. 크기/스트로크/색 사용 규칙을 `UI_REDESIGN.md`에 명문화하면 드리프트 방지.

## 4. 🙋 사용자 관점 보완점

1. **사용 설명서/도움말 부재** — 기능은 많은데 배울 방법이 툴팁(`InfoHint`)뿐. → `USER_GUIDE.md`(본 세션 작성) + 인앱 도움말 링크(? 버튼 → 가이드).
2. **기본 제공 에셋 라이브러리 없음** — GLB를 직접 구해와야 함(재확인된 최대 진입장벽). 무료 스타터 팩(캐릭터·가구·자연물·건물 각 10~20종)을 플랫폼 기본 제공. 마켓플레이스(P5-03)의 전 단계.
3. **게임 세이브/로드·리더보드** — persistent 변수(localStorage)는 있으나 명시적 세이브 슬롯·점수 랭킹 없음(GAME_LOGIC.md 로드맵). 게임 "완성품" 느낌의 마지막 조각.
4. **완성 예제 템플릿 부족** — 씬 템플릿 5종(쇼룸/갤러리 등)은 "공간" 위주. **완성된 예제 게임**(동전 수집·미로 탈출·방탈출·퀴즈)을 리믹스 가능하게 제공 → 로직 학습 자료 겸용.
5. **게시 씬 SEO/공유 커스터마이즈** — OG 이미지·메타 설명 설정 UI. 커스텀 도메인 쓰는 비즈니스 사용자에게 중요.
6. **방문자 분석 대시보드** — 애널리틱스 이벤트(interact 등)는 쌓는데 보는 화면이 없음.
7. **댓글/피드백 모드** (P4-09) — 협업 전 단계로 "읽기 전용 공유 링크 + 위치 고정 코멘트"가 실시간 협업(P5-01)보다 훨씬 저비용·고효과.

## 7. 결론

기능 폭은 이미 경쟁 서비스(Spline 등)와 견줄 수준이며, 특히 **게임 로직 + 애니메이션 타임라인 + 임베드 브릿지** 조합은 차별화 포인트가 뚜렷하다. 현재 가장 큰 갭은 기능이 아니라 **(1) 배우는 방법(가이드·템플릿·에셋), (2) 신뢰성(오토세이브·테스트·모니터링)** — 즉 "만들 수 있는 것"과 "일반인이 실제로 만드는 것" 사이의 간극이다. 단기 우선순위를 여기에 두는 것을 권장한다.
